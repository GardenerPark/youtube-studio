# Gemini 웹앱용 프롬프트

API 없이 gemini.google.com 에서 직접 분석할 때 쓴다.
모델은 **2.5 Pro** 이상을 고르고, 프롬프트 맨 위 URL만 바꿔서 그대로 붙여넣는다.

프롬프트는 세 가지다. 순서대로 같은 채팅에서 이어 쓰면 영상을 한 번만 보고 세 결과를 다 받을 수 있다.

| # | 용도 | 결과 형태 |
|---|---|---|
| A | 사람이 읽는 장면별 연출 분석 (vidIQ 시청 분석과 같은 형태) | 마크다운 |
| B | 내레이션 전문 받아쓰기 | 타임스탬프 + 대사 |
| C | 캡컷 드래프트용 장면 계획 | JSON → `scene_plan.json` |

---

## A. 장면별 연출 분석 (vidIQ 스타일 마크다운)

`videos/<영상ID>/analysis.md`의 원재료다. 결과를 그대로 저장해도 되고, 요약해서 정리해도 된다.

```
이 유튜브 영상을 처음부터 끝까지 영상과 오디오 모두 보고 분석해 주세요:
https://www.youtube.com/watch?v=L8OVETatbd0

이 영상을 캡컷 템플릿으로 재현하기 위한 상세 편집 분석을 장면별로 작성해 주세요.
장면마다 `### Scene N: 장면 이름 (mm:ss–mm:ss)` 제목을 달고, 아래 항목을 각각 한 줄씩 적어 주세요.

- 카메라 앵글과 프레이밍 (POV, 토킹헤드, 와이드, 저각, 클로즈업 등)
- 장소
- 조명
- 색보정 (예: 흑백, 웜톤, 쿨톤)
- 컷 방식과 다음 장면으로의 전환
- 화면 텍스트: 챕터 타이틀과 캡션의 **정확한 원문**과 나타나는 시각(mm:ss), 보이면 글꼴 스타일도
- 배경음악: 장르, 템포, 악기, 내레이션 아래에서 볼륨이 내려가는지, 시작·종료·급정지 시각
- 사운드 디자인 (디제틱 사운드, 효과음)

장면 분석이 끝나면 `### Summary` 아래에 다음을 정리해 주세요.
- 전체 구조 (파트별 시간 구간)
- 반복되는 시그니처 샷
- 모든 챕터 타이틀 카드의 시각과 원문 목록
- 모든 음악 변경 시각과 성격을 적은 음악 큐 목록
- 음악이 전혀 없는 구간 목록

시간은 영상 플레이어 기준 mm:ss로, 어림하지 말고 실제 전환 시각을 적어 주세요.
```

## B. 내레이션 전문

```
같은 영상의 내레이션과 대화를 처음부터 끝까지 받아써 주세요.
- 5~10초 단위로 줄을 나누고 각 줄 앞에 [mm:ss]를 붙여 주세요.
- 발화 언어 그대로 적고, 번역이나 요약은 하지 마세요.
- 화면 캡션이 아닌 실제 음성만 적어 주세요. 음악만 있는 구간은 [mm:ss] (음악) 으로 표시해 주세요.
- 길면 끊지 말고 끝까지 이어서 써 주세요. 끊기면 제가 "이어서"라고 할게요.
```

## C. 캡컷 드래프트용 JSON

결과 JSON을 `videos/<영상ID>/scene_plan_gemini.json`으로 저장하면 아래 "받은 결과 넣는 법"으로 `make_capcut_draft.py`에 바로 들어간다.

```
이 유튜브 영상을 처음부터 끝까지 영상과 오디오 모두 보고 분석해 주세요:
https://www.youtube.com/watch?v=L8OVETatbd0

당신은 이 영상을 캡컷 템플릿으로 재현하려는 시니어 영상 편집자입니다.
아래 JSON 형식 **하나만** 출력하세요. 설명 문장, 마크다운 코드펜스 바깥의 텍스트는 넣지 마세요.

규칙
- 모든 시간은 영상 시작 기준 **초 단위 숫자**입니다 (예: 83.5). "01:23" 같은 문자열 금지.
- shots는 0초부터 영상 끝까지 빈틈 없이, 서로 겹치지 않게 15~40개.
- music은 실제 배경음악이 흐르는 구간만. 음악 없는 구간은 비워 두고, 겹치지 않게.
  급정지(테이프 스톱)나 페이드가 있으면 notes에 적기.
- subtitles는 화면에 뜨는 캡션/자막을 **보이는 그대로** 전부, 나타나고 사라지는 시간과 함께.
- titles는 챕터 타이틀 카드와 전면 텍스트 카드만.
- script_beats는 내레이션을 순서대로 8~20개로 요약하고, 각 비트마다 실제 발화 언어 그대로의 핵심 대사 한 줄.
- 같은 목록 안에서 구간이 겹치면 안 됩니다. 어림수보다 정확한 값을 우선하세요.

{
  "title": "영상 제목",
  "channel": "채널명",
  "duration_sec": 0,
  "structure_summary": "전체 구조 3~6문장",
  "script_beats": [
    {"start": 0, "end": 0, "beat": "무슨 말을 하는지 한 문장", "key_quote": "실제 대사 그대로"}
  ],
  "shots": [
    {"id": "s01", "start": 0, "end": 0, "label": "장면 이름",
     "shot_type": "카메라/프레이밍 (POV, 토킹헤드, 와이드, 저각, 클로즈업 ...)",
     "location": "장소", "grade": "color | bw | mixed",
     "notes": "조명, 다음 샷으로의 전환 방식, 디제틱 사운드"}
  ],
  "music": [
    {"id": "m01", "start": 0, "end": 0, "genre": "장르", "mood": "무드",
     "volume": 0.5, "duck_under_narration": true,
     "fade_in": 0, "fade_out": 0, "notes": ""}
  ],
  "subtitles": [
    {"start": 0, "end": 0, "text": "화면 캡션 원문"}
  ],
  "titles": [
    {"start": 0, "end": 0, "text": "타이틀 원문",
     "style": "serif | sans | handwritten | mono",
     "size": 12, "color": "#FFFFFF", "bold": false}
  ]
}
```

## 받은 결과 넣는 법

1. Gemini가 준 JSON을 `videos/L8OVETatbd0/scene_plan_gemini.json`으로 저장한다.
2. 아래 명령으로 누락 필드를 채우고 드래프트까지 만든다.

```bash
python3 pipeline/merge_gemini_output.py videos/L8OVETatbd0/scene_plan_gemini.json videos/L8OVETatbd0/scene_plan.json
python3 pipeline/make_capcut_draft.py videos/L8OVETatbd0/scene_plan.json videos/L8OVETatbd0/draft_out/
```

겹치는 구간은 merge 단계에서 앞 구간 끝을 잘라 맞춘다. 결과가 이상하면 scene_plan.json을 손으로 고치고 2번 명령만 다시 돌리면 된다.

## 팁

- 23분 영상은 한 번에 들어간다. 1시간 넘는 영상은 "0분~30분만", "30분~끝까지"로 나눠 요청하고 JSON을 합친다.
- 답이 중간에 끊기면 "이어서 JSON을 완성해 줘"라고 하면 이어 쓴다.
- 자막 전문이 따로 필요하면 같은 채팅에서 "전체 내레이션을 타임스탬프와 함께 받아써 줘"라고 추가로 요청한다.
